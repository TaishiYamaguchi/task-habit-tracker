# Agent Skills（AI支援）開発方針

## 目的

このプロジェクトでは、GitHub Copilot などの AI 支援ツール（Agent Skills）を積極的に活用し、開発効率とドキュメント品質の向上を図ります。
AI の活用は、メンテナーが担う学習・意思決定の主体性を損なわない範囲で行います。

## 優先領域

AI 支援の適用は、以下の順序で優先します。

1. **ドキュメント整備** — README、設計ドキュメント、ガイドラインの追加・改善
2. **テスト追加** — 既存動作を検証するユニットテスト・統合テストの補完
3. **リファクタリング** — 機能を変えずにコードの可読性・保守性を高める変更

## AI に許可する作業範囲

AI（Agent Skills）は次の作業を自律的に行い、Pull Request を作成できます。

- ドキュメントの新規作成・修正（README、`docs/` 配下のファイルなど）
- 既存テストを壊さないテストコードの追加
- 動作を変えないリファクタリング（変数名変更、コード整理など）
- 軽微なバグ修正（スコープが明確で影響範囲が限定的なもの）

## 「小さな変更」の考え方

AI が単独で PR を作成してよい変更は、以下の基準を満たす **小さな変更** に限ります。

- **動作を保持する（behavior-preserving）**: 外部から観察できる振る舞いを変えない
- **スコープが限定的**: 変更対象のファイル・モジュールが明確に絞られており、予期しない副作用が生じにくい

数値的な閾値（行数・ファイル数など）は設けません。上記の性質を満たすかどうかで判断します。

## AI に許可しない（または事前合意が必要な）作業

以下の作業は、メンテナーとの事前合意なしに AI が単独で行うことを禁止します。

- 新機能の設計・実装（アーキテクチャに影響するもの）
- 依存ライブラリの追加・バージョン変更
- セキュリティ設定の変更（認証・認可・シークレット管理など）
- データベーススキーマの変更
- CI/CD パイプラインの変更
- 既存テストの削除・無効化

## レビュー運用

| 変更の種類 | レビュー方針 |
|---|---|
| ドキュメントのみの変更 | 軽いレビューで可（誤字・リンク・内容の整合性を確認） |
| テスト追加・リファクタリング | 通常レビュー（動作保証・意図の確認） |
| 機能変更・バグ修正 | 通常レビュー（変更の影響範囲を必ず確認） |

最終的なマージ判断は常にメンテナーが行います。

## PR 作成時の最低要件

AI が作成する Pull Request には、以下を含めること。

- 変更の目的と内容の要約
- 採用したガバナンスモデル（「ドキュメント優先」「小さな変更」など）の明示
- 関連する Issue や背景へのリンク（あれば）
- レビュアーへの確認ポイント（あれば）

## 情報取り扱い

- AI ツールに対して、シークレット・個人情報・未公開の機密情報を入力しないこと。
- `.env` ファイルや認証情報は絶対に AI のプロンプトに含めないこと。
- AI が生成したコード・ドキュメントは、マージ前にメンテナーが内容を確認・責任を持つこと。

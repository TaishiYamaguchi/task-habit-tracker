# 機能ロードマップ

このドキュメントでは、Task & Habit Tracker の段階的な開発計画を詳細に説明します。各フェーズには具体的な機能と、その機能を通じて学ぶべき技術要素を記載しています。

## 概要

```
Phase 1: MVP          Phase 2: 機能拡張      Phase 3: 高度な機能
(1-2週間)            (+1-2週間)            (継続的)
┌─────────────┐      ┌─────────────┐       ┌─────────────┐
│ ユーザー認証  │      │ 習慣トラッキング│       │ 外部API連携  │
│ タスクCRUD   │  →   │ カレンダー表示 │   →   │ 通知機能     │
│ 基本UI      │      │ カテゴリ/タグ  │       │ チーム機能   │
└─────────────┘      └─────────────┘       └─────────────┘
```

---

## Phase 1: MVP (Minimum Viable Product)

**目標期間**: 1-2週間

このフェーズでは、アプリケーションの基盤を構築し、核となる機能を実装します。

### 1.1 ユーザー登録・ログイン

#### 機能要件

| 機能 | 詳細 |
|------|------|
| ユーザー登録 | メールアドレス、パスワードでアカウント作成 |
| ログイン | JWT認証によるログイン |
| ログアウト | トークン破棄 |
| パスワード保存 | BCryptによるハッシュ化 |

#### API エンドポイント

```
POST /api/auth/register   # ユーザー登録
POST /api/auth/login      # ログイン
POST /api/auth/logout     # ログアウト（将来的にリフレッシュトークン対応時）
```

#### 学習目標

- [ ] Spring Security の設定と理解
- [ ] JWT トークンの生成と検証
- [ ] パスワードのセキュアな保存方法
- [ ] 認証フローの設計
- [ ] React でのトークン管理

#### 実装チェックリスト

- [ ] `User` エンティティ作成
- [ ] `UserRepository` 作成
- [ ] `AuthService` 作成（登録、ログイン処理）
- [ ] `JwtTokenProvider` 作成
- [ ] `SecurityConfig` 設定
- [ ] 登録・ログインフォーム（フロントエンド）
- [ ] 認証状態管理（React Context）
- [ ] Protected Route 実装

### 1.2 タスク CRUD 操作

#### 機能要件

| 機能 | 詳細 |
|------|------|
| タスク作成 | タイトル、説明、期限を設定 |
| タスク一覧 | ユーザーのタスクを一覧表示 |
| タスク更新 | タイトル、説明、期限、ステータスを更新 |
| タスク削除 | タスクを削除 |

#### API エンドポイント

```
GET    /api/tasks         # タスク一覧取得
GET    /api/tasks/:id     # タスク詳細取得
POST   /api/tasks         # タスク作成
PUT    /api/tasks/:id     # タスク更新
DELETE /api/tasks/:id     # タスク削除
```

#### データモデル

```typescript
interface Task {
  id: number;
  title: string;
  description?: string;
  status: 'TODO' | 'IN_PROGRESS' | 'DONE';
  dueDate?: string;
  completedAt?: string;
  createdAt: string;
  updatedAt: string;
}
```

#### 学習目標

- [ ] Spring Data JPA によるCRUD操作
- [ ] DTO パターンの活用
- [ ] バリデーション（Jakarta Validation）
- [ ] 例外処理とエラーレスポンス
- [ ] React でのフォーム処理
- [ ] TanStack Query によるサーバーステート管理

#### 実装チェックリスト

- [ ] `Task` エンティティ作成
- [ ] `TaskRepository` 作成
- [ ] `TaskService` 作成
- [ ] `TaskController` 作成
- [ ] リクエスト/レスポンス DTO 作成
- [ ] バリデーション実装
- [ ] タスク一覧コンポーネント
- [ ] タスク作成/編集フォーム
- [ ] 削除確認ダイアログ

## Phase 2: 機能拡張

**目標期間**: 追加 1-2週間

MVPの基盤の上に、より使いやすい機能を追加します。

### 2.1 習慣トラッキング

#### 機能要件

| 機能 | 詳細 |
|------|------|
| 習慣作成 | 日次/週次の習慣を定義 |
| 習慣記録 | 日々の達成を記録 |
| 連続記録 | ストリーク（連続達成日数）を表示 |

#### データモデル

```typescript
interface Habit {
  id: number;
  name: string;
  description?: string;
  frequency: 'DAILY' | 'WEEKLY';
  targetCount: number;  // 1日の目標回数
  color?: string;
  isActive: boolean;
  createdAt: string;
}

interface HabitRecord {
  id: number;
  habitId: number;
  recordDate: string;  // YYYY-MM-DD
  count: number;
  notes?: string;
}
```

#### 学習目標

- [ ] 新しいドメインモデルの追加
- [ ] 日付ベースのデータ集計
- [ ] カスタムクエリ（Spring Data JPA）

## Phase 3: 高度な機能

**目標期間**: 継続的に実装

より高度な機能を追加し、実践的なスキルを身につけます。

### 3.1 外部API連携（天気API）

#### 機能要件

| 機能 | 詳細 |
|------|------|
| 天気情報取得 | 現在地の天気を表示 |
| 天気ベースの提案 | 「雨の日はインドアタスクを」のような提案 |

#### 学習目標

- [ ] 外部REST API呼び出し（RestTemplate / WebClient）
- [ ] API キーの安全な管理
- [ ] レスポンスのキャッシュ

---

### 3.2 リマインダー通知

#### 機能要件

| 機能 | 詳細 |
|------|------|
| 期限通知 | タスク期限前にリマインダー |
| ブラウザ通知 | Web Push API |
| 通知設定 | 通知のオン/オフ、タイミング設定 |

#### 技術オプション

- **WebSocket**: リアルタイム双方向通信
- **Server-Sent Events (SSE)**: サーバーからのプッシュ
- **Web Push API**: ブラウザ通知

#### 学習目標

- [ ] WebSocket / SSE の実装
- [ ] プッシュ通知の仕組み
- [ ] バックグラウンドジョブ（スケジューリング）

---

### 3.3 チーム機能

| 共有タスク | チーム内でタスクを共有 |
| タスク割り当て | タスクをメンバーに割り当て |

#### 学習目標

- [ ] マルチテナンシーの考慮

---

### Phase 3 機能優先度

| 優先度 | 機能 | 理由 |
|--------|------|------|
| 高 | 外部API連携 | API統合の基礎スキル |
| 高 | 通知機能 | リアルタイム技術の習得 |
| 中 | チーム機能 | 複雑なドメインモデル |
| 中 | ファイル添付 | ファイル処理の基礎 |
